# Таблиці бази даних JoicreMemory для звіту

Нижче наведено таблиці, які відповідають реальному SQL-скрипту `database/schema.sql`.

Увага: паролі користувачів не зберігаються у PostgreSQL, оскільки авторизація реалізована через Firebase Auth. Повідомлення чатів також не зберігаються в PostgreSQL, оскільки їх зберігає Stream Chat SDK.

---

## Таблиця 5.1 - Структура таблиці `users` (Користувачі)

| Назва поля | Тип даних | Опис / Обмеження |
|---|---|---|
| `id` | UUID | Первинний ключ (PK), унікальний ідентифікатор користувача. Значення автоматично генерується функцією `gen_random_uuid()`. |
| `firebase_uid` | TEXT | Унікальний ідентифікатор користувача у Firebase Auth. Поле є обов'язковим (`NOT NULL`) та унікальним (`UNIQUE`). |
| `email` | CITEXT | Електронна пошта користувача. Поле є обов'язковим (`NOT NULL`), унікальним (`UNIQUE`) та нечутливим до регістру символів. |
| `full_name` | TEXT | Ім'я користувача. Поле є обов'язковим (`NOT NULL`). Довжина значення повинна бути від 2 до 120 символів. |
| `avatar_url` | TEXT | Посилання на аватар користувача. Поле необов'язкове. |
| `bio` | TEXT | Коротка інформація про користувача. Поле необов'язкове, максимальна довжина - 500 символів. |
| `phone` | TEXT | Номер телефону користувача. Поле необов'язкове. |
| `stream_user_id` | TEXT | Ідентифікатор користувача у Stream Chat. Поле є унікальним (`UNIQUE`) та використовується для підключення до чатів. |
| `created_at` | TIMESTAMPTZ | Дата і час створення запису. За замовчуванням встановлюється поточний час (`DEFAULT NOW()`). |
| `updated_at` | TIMESTAMPTZ | Дата і час останнього оновлення запису. Автоматично оновлюється тригером `set_updated_at()`. |

## Таблиця 5.2 - Структура таблиці `events` (Події)

| Назва поля | Тип даних | Опис / Обмеження |
|---|---|---|
| `id` | UUID | Первинний ключ (PK), унікальний ідентифікатор події. Значення автоматично генерується функцією `gen_random_uuid()`. |
| `creator_user_id` | UUID | Зовнішній ключ (FK) на таблицю `users(id)`. Визначає користувача, який створив подію. При видаленні користувача пов'язані події видаляються каскадно (`ON DELETE CASCADE`). |
| `title` | TEXT | Назва події. Поле є обов'язковим (`NOT NULL`). Довжина назви повинна бути від 3 до 140 символів. |
| `description` | TEXT | Детальний опис події. Поле є обов'язковим (`NOT NULL`). Довжина опису повинна бути від 10 до 5000 символів. |
| `category` | TEXT | Категорія події. Допустимі значення: `volunteering`, `charity`, `cleanup`, `education`, `community`, `emergency`, `other`. |
| `status` | TEXT | Статус події. За замовчуванням - `published`. Допустимі значення: `draft`, `published`, `cancelled`, `completed`. |
| `location_name` | TEXT | Назва місця проведення події. Поле є обов'язковим (`NOT NULL`). |
| `address` | TEXT | Текстова адреса події. Поле необов'язкове. |
| `latitude` | NUMERIC(9,6) | Географічна широта місця проведення. Поле є обов'язковим (`NOT NULL`). Значення повинно бути в межах від -90 до 90. |
| `longitude` | NUMERIC(9,6) | Географічна довгота місця проведення. Поле є обов'язковим (`NOT NULL`). Значення повинно бути в межах від -180 до 180. |
| `geo` | GEOGRAPHY(Point, 4326) | Просторове поле PostGIS, яке автоматично формується на основі `latitude` та `longitude`. Використовується для геопросторового пошуку подій. |
| `starts_at` | TIMESTAMPTZ | Дата і час початку події. Поле є обов'язковим (`NOT NULL`). |
| `ends_at` | TIMESTAMPTZ | Дата і час завершення події. Поле необов'язкове. Якщо значення задане, воно не може бути меншим за `starts_at`. |
| `max_participants` | INTEGER | Максимальна кількість учасників події. Поле необов'язкове. Якщо значення задане, воно повинно бути в межах від 1 до 10000. |
| `image_url` | TEXT | Посилання на зображення події. Поле необов'язкове. |
| `created_at` | TIMESTAMPTZ | Дата і час створення запису. За замовчуванням встановлюється поточний час (`DEFAULT NOW()`). |
| `updated_at` | TIMESTAMPTZ | Дата і час останнього оновлення запису. Автоматично оновлюється тригером `set_updated_at()`. |

## Таблиця 5.3 - Структура таблиці `event_participants` (Учасники подій)

| Назва поля | Тип даних | Опис / Обмеження |
|---|---|---|
| `event_id` | UUID | Частина складеного первинного ключа (PK) та зовнішній ключ (FK) на таблицю `events(id)`. При видаленні події записи участі видаляються каскадно (`ON DELETE CASCADE`). |
| `user_id` | UUID | Частина складеного первинного ключа (PK) та зовнішній ключ (FK) на таблицю `users(id)`. При видаленні користувача його записи участі видаляються каскадно (`ON DELETE CASCADE`). |
| `role` | TEXT | Роль користувача в межах події. За замовчуванням - `participant`. Допустимі значення: `organizer`, `participant`. |
| `status` | TEXT | Статус участі користувача. За замовчуванням - `joined`. Допустимі значення: `joined`, `pending`, `cancelled`. |
| `created_at` | TIMESTAMPTZ | Дата і час створення запису про участь. За замовчуванням встановлюється поточний час (`DEFAULT NOW()`). |
| `updated_at` | TIMESTAMPTZ | Дата і час останнього оновлення запису. Автоматично оновлюється тригером `set_updated_at()`. |

Первинний ключ таблиці є складеним: (`event_id`, `user_id`). Це не дозволяє одному користувачу бути доданим до однієї і тієї ж події кілька разів.

## Таблиця 5.4 - Структура таблиці `event_chat_channels` (Чат-канали подій)

| Назва поля | Тип даних | Опис / Обмеження |
|---|---|---|
| `id` | UUID | Первинний ключ (PK), унікальний ідентифікатор запису про чат-канал. Значення автоматично генерується функцією `gen_random_uuid()`. |
| `event_id` | UUID | Зовнішній ключ (FK) на таблицю `events(id)`. Поле є унікальним (`UNIQUE`), оскільки одна подія має один чат-канал. При видаленні події запис чат-каналу видаляється каскадно (`ON DELETE CASCADE`). |
| `stream_channel_id` | TEXT | Унікальний ідентифікатор каналу у Stream Chat. Поле є обов'язковим (`NOT NULL`) та унікальним (`UNIQUE`). |
| `avatar_url` | TEXT | Посилання на аватар групового чату події. Поле необов'язкове. Якщо значення задане, воно повинно починатися з `http://` або `https://`. |
| `created_by_user_id` | UUID | Зовнішній ключ (FK) на таблицю `users(id)`. Визначає користувача, який створив чат-канал. При видаленні користувача запис видаляється каскадно (`ON DELETE CASCADE`). |
| `created_at` | TIMESTAMPTZ | Дата і час створення запису. За замовчуванням встановлюється поточний час (`DEFAULT NOW()`). |
| `updated_at` | TIMESTAMPTZ | Дата і час останнього оновлення запису. Автоматично оновлюється тригером `set_updated_at()`. |

## Додатково: індекси бази даних

| Назва індексу | Таблиця / поле | Призначення |
|---|---|---|
| `idx_users_firebase_uid` | `users(firebase_uid)` | Швидкий пошук користувача за Firebase UID. |
| `idx_users_stream_user_id` | `users(stream_user_id)` | Швидкий пошук користувача за ідентифікатором Stream Chat. |
| `idx_events_creator_user_id` | `events(creator_user_id)` | Швидкий пошук подій, створених конкретним користувачем. |
| `idx_events_status_starts_at` | `events(status, starts_at)` | Оптимізація вибірки подій за статусом та датою початку. |
| `idx_events_category_status` | `events(category, status)` | Оптимізація фільтрації подій за категорією та статусом. |
| `idx_events_geo` | `events USING GIST (geo)` | Геопросторовий індекс PostGIS для пошуку подій за координатами. |
| `idx_events_published_geo` | `events USING GIST (geo) WHERE status = 'published'` | Частковий геоіндекс для швидкого пошуку лише опублікованих подій. |
| `idx_event_participants_user_id` | `event_participants(user_id)` | Швидкий пошук подій, у яких бере участь користувач. |
| `idx_event_participants_event_role` | `event_participants(event_id, role)` | Швидкий пошук ролей користувачів у межах події. |
| `idx_event_chat_channels_event_id` | `event_chat_channels(event_id)` | Швидкий пошук чат-каналу за подією. |
